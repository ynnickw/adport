# Meta app campaigns

The named app tools share the same definitions in CLI, local MCP and hosted MCP. Use `meta_advertisable_applications` with the selected `account_id` to discover the Meta application ID and its native store URLs. The Meta application ID differs from the numeric App Store ID. The read uses only the selected ad account's `advertisable_applications` edge and never requests app credentials. Pass `next_cursor` as `after` with the same account and filters to continue.

`meta_create_campaign` accepts `promoted_object.application_id`, `promoted_object.object_store_url` and `is_skadnetwork_attribution`. The typed app binding requires `OUTCOME_APP_PROMOTION`. SKAdNetwork requires both the application ID and its store URL at campaign creation; the tool rejects either missing field before making a native request. Other app campaigns may omit the store URL at campaign level. The tool does not attempt to repair an existing unbound SKAdNetwork campaign by changing its immutable app binding.

`meta_create_ad_set` accepts an explicit `promoted_object` with both `application_id` and `object_store_url`, plus optional `user_os` targeting strings. Explicit app binding defaults optimization to `APP_INSTALLS`; other ad sets retain `LINK_CLICKS`. Billing defaults to `IMPRESSIONS`. Before preview and apply, Adport reads the parent campaign, verifies its ID and account, requires an app-promotion objective and checks any existing app/store binding for a match. The app must also appear in the account's filtered advertisable-app inventory. The tool does not silently infer an app from the parent or switch to a different app.

Store URLs accept HTTP or HTTPS without embedded credentials or fragments, including the legacy `http://itunes.apple.com/...` URLs Meta returns in app inventory. Adport passes the URL to Meta as a field and does not fetch it.

Both creation tools keep Meta's `execution_options=["validate_only"]` preview, the shared pending-token apply gate, paused-creation policy and budget caps in micros. Native Meta validation remains authoritative for OS strings, attribution, app-store compatibility, account eligibility and bidding combinations. Parent/app checks are repeated at apply, but Meta does not provide an atomic compare-and-set for concurrent parent changes. Creation does not add creatives or ads.

`meta_get_campaign` and `meta_list_campaigns` include native SKAdNetwork and app-binding fields when Meta supplies them, so an agent can inspect the setup without using the dashboard or a generic API dispatcher.

Wire fields follow the official Business SDK pinned to [AdAccount](https://github.com/meta/facebook-python-business-sdk/blob/99b5e2db19e60e63f753154b36dad684cbbd3088/facebook_business/adobjects/adaccount.py), [AdPromotedObject](https://github.com/meta/facebook-python-business-sdk/blob/99b5e2db19e60e63f753154b36dad684cbbd3088/facebook_business/adobjects/adpromotedobject.py), [Application](https://github.com/meta/facebook-python-business-sdk/blob/99b5e2db19e60e63f753154b36dad684cbbd3088/facebook_business/adobjects/application.py) and [Targeting](https://github.com/meta/facebook-python-business-sdk/blob/99b5e2db19e60e63f753154b36dad684cbbd3088/facebook_business/adobjects/targeting.py).
