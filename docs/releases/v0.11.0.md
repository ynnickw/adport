# v0.11.0

## TikTok catalog transfers

- Read transfer context and preview/apply an exact advertiser-owned catalog transfer to a Business Center with `tiktok_catalog_migration_context` and `tiktok_migrate_catalog`. The project owner must separately attest source ownership and authorize the exact catalog and destination. Native Admin checks, fresh delegation/destination hashes and destination readback protect the transfer; ongoing project read/write access is unchanged. ([#179](https://github.com/ynnickw/adport/pull/179))
- Pixel permission errors distinguish developer-app approval from advertiser authorization. Reconnecting an advertiser cannot add an app permission that TikTok has not approved. The requested Pixel management permission remains a separate provider review.

## Agent uploads and hosted discovery

- Hosted MCP reports its installed package version instead of the fixed `0.1.0`. Discovery checks cover both HTTP transports, native attachment fields, project routing and CSV support. ([#179](https://github.com/ynnickw/adport/pull/179))
- Attachment download capabilities and inline/part-upload base64 contents stay out of widget approval arguments. Agents and direct widget uploads still use the same exact-argument preview/apply gate. Human-readable previews retain the approved file metadata.
- GA4 read-only connections are available to all Adport Cloud projects after Google verification. Each user must consent and select accessible properties. This approval covers only `analytics.readonly`; self-hosters need their own application's approval.

## Upgrade notes

- Install the CLI with `npm install -g adport@0.11.0`. All public packages share version `0.11.0` and require Node.js 22.13 or later. Restart local MCP clients and refresh hosted connector tools after upgrading.
- Cloud operators must apply `supabase/migrations/20261119135249_tiktok_catalog_migration_access.sql` before deploying this build. It adds catalog-transfer delegation modes without changing existing grants, RLS or backend-only privileges. The migration does not delegate or transfer any catalog.
- Catalog transfers affect the entire shared catalog and have no automatic retry or rollback. Source ownership is owner-attested and enforced by TikTok on apply. Native transfers require separately identified and approved source/destination resources.
- A GitHub/npm release does not deploy Cloud. Keep the production deployment, release tag and reviewed main commit aligned through the existing release process.

## Validation

Release checks cover repository hygiene, builds, typechecks, provider contract/policy tests and isolated package installation. The release workflow verifies public npm installation before publishing the GitHub release.

The upload privacy regression was reproduced before the fix. Tests verify that previews do not contain attachment capabilities or file bytes, changed arguments still reject, and only the matching approved operation applies. These tests do not establish native ChatGPT attachment handoff, native widget-picker operation or TikTok approval. Live host verification and provider approval must be recorded separately from server contract tests.
