# v0.11.1

## Changes

ChatGPT attachment imports now accept the signed `https://chatgpt.com/backend-api/estuary/content` download route, alongside `files.oaiusercontent.com`. Native delivery was observed using this route on November 20, 2026; v0.11.0 rejected it before downloading.

Only the exact ChatGPT attachment path with nonempty `id` and `sig` parameters is accepted. Downloads still omit credentials, reject redirects and enforce the existing size, media validation, checksum, project authorization and preview/apply checks. Other ChatGPT API paths and lookalike hosts remain rejected.

## Upgrade notes

No migration or credential changes are required. Refresh an expired attachment reference and inspect it again before previewing an import. This patch does not add support for arbitrary URLs or change provider permissions.

## Validation

The regression test reproduced the native route rejection before the fix. All 28 attachment transport tests pass, including invalid origins, unrelated ChatGPT paths, missing capability parameters and credential-free requests. Local repository checks, build and typecheck pass; the full suite passes 5,114 tests, with 157 credential-dependent tests skipped. Native end-to-end import remains pending deployment verification.
