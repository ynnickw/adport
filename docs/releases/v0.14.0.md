# v0.14.0

## Changes

- Connect a Matomo site or Google Analytics 4 property to an Adport project and use the same two read-only tools in the CLI, MCP and Cloud API. `analytics_goals` lists conversion definitions and their IDs. `analytics_acquisition_report` returns sessions, conversions and revenue by source, medium and campaign for a date range, with an optional landing-page breakdown. [Matomo and shared analytics, #205](https://github.com/ynnickw/adport/pull/205)
- Connect a Gravity advertiser in Adport Cloud. Read access is the default. Owners and admins can also authorize campaign edits and spend changes. Gravity tools cover ads, campaigns, ad groups, pixels, conversions and billing. Changes use Adport’s preview and approval flow. [Gravity, #203](https://github.com/ynnickw/adport/pull/203)

## Upgrade notes

- **Breaking change for GA4 callers.** Update saved acquisition requests that use `ga4_report` to call `analytics_acquisition_report` with `provider: "ga4"` and the property ID. Use `analytics_goals` for key events and the native analytics provider for arbitrary reports, metadata or realtime analysis. [Website analytics migration guide](https://github.com/ynnickw/adport/blob/v0.14.0/docs/providers/website-analytics.md)
- For hosted Matomo OAuth, register Adport once on each Matomo instance with the OAuth 2.0 plugin and the exact callback shown during setup. A view-only personal token is also supported. The Marketing Campaigns Reporting plugin supplies Matomo’s source and medium breakdown. The report identifies unavailable dimensions. [Matomo setup](https://github.com/ynnickw/adport/blob/v0.14.0/docs/providers/matomo.md)
- Gravity’s hosted OAuth uses the advertiser owner or admin’s login. Self-hosted CLI and MCP users can use an advertiser API key. [Gravity setup](https://github.com/ynnickw/adport/blob/v0.14.0/docs/providers/gravity.md)
- CLI users can install `adport@0.14.0`. For self-hosted MCP, update to `@adport/mcp@0.14.0` and restart the server. Self-hosted Cloud operators should apply the four Matomo and Gravity database migrations before deploying.

## Validation

A view-only account on a test Matomo 6 installation completed OAuth and read a configured goal and tracked conversion. Gravity’s live authorization endpoint redirected to its advertiser consent page. The Gravity token lifecycle and eight read and eight approval-gated write workflows were exercised with a local simulator. Completing consent and reading a live Gravity campaign require an approved advertiser account.
