# v0.9.0

## Creative library and uploads

- Adport Cloud has a shared creative library per project. Upload images, videos, audio, PDFs, and CSVs from the dashboard or a supported MCP widget. The dashboard supports multi-file upload, previews, channel tags, and pagination.
- Hosted MCP and CLI clients can stage media in the project library and reuse its file reference for supported provider uploads. Provider changes still use the preview and approval flow.

## Provider tools

- Expanded creative and campaign management across the supported advertising providers, including TikTok image and video tools, Pinterest and Reddit catalog operations, and Microsoft offline conversion tools.
- Added Google Tag Manager configuration tools with guarded publishing, plus read-only Google Analytics and Search Console tools. Availability depends on connected accounts, OAuth grants, and the selected tool catalog.
- Hosted connections can select a tool profile and provider set. Compact tool discovery and widget resources support clients with smaller payload limits. Existing approvals remain bound to the previewed arguments and project.

## Upgrade notes

- Install the CLI with `npm install -g adport@0.9.0`. Public packages share version `0.9.0` and require Node.js 22.13 or later. Restart local MCP clients after upgrading to refresh tool and widget discovery.
- Cloud self-hosters should apply the migrations included in this tag before starting the new Cloud build. They cover creative storage, tool profiles, provider resource grants, and Google analytics connections.
- Provider permissions and account eligibility still determine which actions can run. TikTok creative uploads require the app and advertiser grants. Reddit existing catalogs require explicit access. File upload availability depends on the MCP host's file capabilities.

## Validation

The release workflow checks the tagged source, builds and type-checks the workspace, runs tests, and verifies a public npm installation before publishing the GitHub release. Provider contract tests use mocked responses. Database, live-provider, and embedded host checks have separate coverage.
