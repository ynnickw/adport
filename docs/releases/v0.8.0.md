# v0.8.0

## Compact widgets and clearer approvals

- MCP widgets use consistent Adport branding and provider marks across accounts, reports, recommendations, planning estimates, native records, processing receipts, and creative previews. Tools without a specialized view receive a structured data fallback. Project directories show saved logos with an initials fallback. [#150](https://github.com/ynnickw/adport/pull/150), [#152](https://github.com/ynnickw/adport/pull/152), [#153](https://github.com/ynnickw/adport/pull/153)
- Guarded writes include a shared structured review with proposed changes, observed previous values when available, budget deltas, and policy adjustments. Compact reviews retain hold-to-apply approval, keyboard support, and the existing preview/token/policy gate. Unconfirmed results require a status check before retrying; processing receipts distinguish acceptance from completion. [#150](https://github.com/ynnickw/adport/pull/150), [#152](https://github.com/ynnickw/adport/pull/152)
- Creative galleries show bounded, view-only media previews and ad copy, with native playback controls and full-size images. [#151](https://github.com/ynnickw/adport/pull/151)

## Daily performance reports

- The shared `report` tool accepts `granularity: "day"` for inclusive ranges of up to 31 days. Each observation comes from an exact-date provider read; unavailable dates and metrics remain gaps. Reports retain currency-separated summaries and can display daily trends or aggregate rankings. [#152](https://github.com/ynnickw/adport/pull/152)
- Aggregate reporting remains the default. Daily mode makes one report request per selected provider per day and can therefore use more provider API quota. Responses include the resolved date range, and partial daily failures identify the affected date when `continue_on_error` is enabled. [#152](https://github.com/ynnickw/adport/pull/152)

## Cloud and website changes since v0.7.0

- Assistant authorization can cover all accessible projects in an organization. `projects_list` discovers the available projects and platforms; other hosted tools require `project_id` when multiple projects are available. Membership, roles, account access, and policy are checked in the selected project on every call. Existing single-project grants remain scoped until a new consent. [#143](https://github.com/ynnickw/adport/pull/143), [#147](https://github.com/ynnickw/adport/pull/147)
- Project and organization logo uploads, simpler assistant setup, password-free invitation acceptance, project-specific invitation names, contextual pricing, and in-place billing plan/interval changes improve the dashboard. The website hero animation also has faster pacing. [#138](https://github.com/ynnickw/adport/pull/138), [#141](https://github.com/ynnickw/adport/pull/141), [#142](https://github.com/ynnickw/adport/pull/142), [#145](https://github.com/ynnickw/adport/pull/145), [#135](https://github.com/ynnickw/adport/pull/135), [#140](https://github.com/ynnickw/adport/pull/140), [#146](https://github.com/ynnickw/adport/pull/146), [#148](https://github.com/ynnickw/adport/pull/148), [#149](https://github.com/ynnickw/adport/pull/149)
- Release publication and clean-install verification tolerate npm registry propagation delays while retaining immediate failure for authentication and integrity errors. [#139](https://github.com/ynnickw/adport/pull/139)

Cloud and website deployments, provider application approvals, and connector listings have separate lifecycles. Installing this package release does not deploy those services or change approval status.

## Upgrade notes

- Upgrade the CLI with `npm install -g adport@0.8.0`. All 14 public packages use version `0.8.0`; Node.js 22.13 or later remains required. Restart local MCP clients after upgrading to refresh tool schemas and widgets.
- Existing report calls retain aggregate behavior. Opt into daily observations with `granularity: "day"` and choose a range of at most 31 days. Row limits, truncation, currency separation, and provider permissions still apply.
- The packaged widget resource is `ui://adport/insight-card-v13.html`; previous v2-v12 resources remain aliases. Clients must support MCP Apps to display embedded widgets.
- Cloud self-hosters must apply `20261102134510_workspace_logos.sql` and `20261102134658_mcp_organization_project_access.sql` before deploying the corresponding dashboard and authorization changes. Existing grants must not be backfilled with organization-wide scope. See [organizations and projects](https://github.com/ynnickw/adport/blob/v0.8.0/docs/cloud/organizations-and-projects.md).
- The two-step write gate, policy-bound approval tokens, budget caps, paused creation, and audit logging remain enforced. Provider permissions, account eligibility, and platform reviews still apply; contract tests do not establish live provider acceptance.
